= The GPX Player

While most modules are designed to be used as libraries, they can also be used as standalone applications. +
The `gpx-player.jar` is a standalone application that can be run from the command line. +
It can be used to play GPX tracks and send them to a Traccar server or other endpoints 
and can be helpful for testing and debugging. 

[TIP]
====
If you want to use the GPX Player to playback your own GPX tracks, 
you can head on over +
to the 
xref:./gpx-player-qs.adoc[Quick Start]
guide for instructions on how to get started.
====


== player layers

In the course of development, the gps-osmand-player was split into the two layers for *gpx* loading and *gps* playing.

     bm.gps.player           bm.gps.gpx
            PlayerOsmAnd            Gpx2OsmandLoader
            PlayerTimerRoute        Gpx2OsmandParser
            QuartzSchedulerBean
            --
            PlayerApplication

=== player 

The `player` layer accepts a message list and plays them back to the Tracking System. +
This player is part of the framework and can be used in other modules as well. 

=== gpx

The `gpx` layer is responsible for loading GPX files and converting them into a message list. +
This must not be part of the framework, as it is only needed to access external data sources. +
It can be disabled by setting the property `gps.player.loader-enabled=false` in the `app.props`. +


== player application

The `PlayerApplication` class is not part of the framework, 
but serves as the entry point for the GPX Player application. 
The `spring-boot-maven-plugin` with `mainClass=bm.gps.player.PlayerApplication`
creates a runnable `gpx-player.jar` with all dependencies included. 
The resulting jar can be run on command line, while the plain jar remains a library for other modules.
You can see by the size of the jars that the `gpx-player.jar` is a fat jar with all dependencies included:

          59.702 gps-osmand-tracker-1.1.27.jar
       1.020.846 gps-osmand-player-1.1.27.jar
      40.752.680 gpx-player-1.1.27.jar
                   =

== logging

The GPX Player comes with a default logging configuration that logs to the console and to a log file. + 
You can copy the file out of the jar next to the `gpx-player.jar` and edit it to your needs. 

Different log settings can provide different levels of detail for different aspects. +
We will show some examples of log output for different log levels. +
These are very useful introspection infos for debugging and testing. +
For example you can see the `[thread]s` working in parallel.

=== TODO message content

    but can be enabled by setting the property `gps.player.log-messages=true` in the `app.props`. 
    
Use maven property `-Dgps.player.log-messages=true` to enable logging of messages for a single run.
