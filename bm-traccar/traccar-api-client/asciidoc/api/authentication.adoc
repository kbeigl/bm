== Traccar Authentication

Note that the Traccar API requires authentication for all endpoints and sub APIs.
The authentication is handled by the `TraccarApi` class, 
which provides methods to set and manage authentication credentials.
The authentication is _not_ handled by the individual sub APIs, 
but is a prequisite for using any of the sub APIs.

The Traccar API supports two authentication methods for REST API calls:

* **Bearer Token (API Key)** - Token-based authentication using a service account token
* **HTTP Basic Authentication** - Username (email) and password authentication

[IMPORTANT]
====
Traccar accepts **only one authentication method at a time**. +
When you switch authentication methods, the previous authentication is automatically cleared.
====

// see `AuthenticationIT`

=== Authentication Methods

==== Bearer Token Authentication

Bearer Token authentication uses a token (API Key) to authenticate requests. 
This is commonly used for service accounts or automated systems that need persistent access without user credentials.

===== Setting Bearer Token

[source,java]
----
// Set authentication using a bearer token
api.setBearerToken("YOUR_TRACCAR_TOKEN");

// The token can be obtained from Traccar server configuration
// e.g., traccar.web.serviceAccountToken
----

[NOTE]
====
When you call `setBearerToken()`, any previously set Basic Authentication credentials (username/password) are automatically cleared.
====

===== Virtual Admin / Service Account

The bearer token is often used for a "Virtual Admin" or "Service Account" which has unrestricted access to the Traccar server:

[source,java]
----
// Virtual Admin has full access to all resources
api.setBearerToken(virtualAdminToken);

// Can now perform any operation
List<User> allUsers = api.getUsersApi().getUsers(null, null, null, null);
List<Device> allDevices = api.getDevicesApi().getDevices();
----

==== HTTP Basic Authentication

HTTP Basic Authentication uses an email address and password to authenticate requests. +
This is the standard way for regular users, admins, and managers to access the API.

===== Setting Basic Authentication

[source,java]
----
// Set authentication using email and password
api.setBasicAuth("user@domain.com", "userPassword");
----

// // Now API calls are made with this user's credentials and permissions
// User currentUser = api.getSessionApi().createSession(email, password);


[NOTE]
====
When you call `setBasicAuth()`, any previously set Bearer Token is automatically cleared.
====

===== User Roles and Permissions

Different user roles have different API access levels:

* **Admin** - Full access to users and devices they manage
* **Manager** - Can create and manage a limited number of users and devices
* **Regular User** - Can only access their own user information and assigned devices

[TIP]
====
The Traccar Roles are an important part of the security model! +
They will be described in more detail in the `UsersAPI` and other sections of this documentation.
====


=== Switching Authentication

You can switch between authentication methods at any time during program execution:

[source,java]
----
// Start with Basic Auth
api.setBasicAuth("user@domain.com", "password");
User user = api.getUsersApi().getUser(123L);

// Switch to Bearer Token for admin operations
api.setBearerToken(virtualAdminToken);
List<User> allUsers = api.getUsersApi().getUsers(null, null, null, null);

// Switch back to Basic Auth with different user
api.setBasicAuth("admin@domain.com", "adminPassword");
User newUser = api.getUsersApi().createUser(user);
----

==== Temporary Authentication

When an application needs to execute operations on behalf of another user 
(for example, creating resources or querying devices visible only to that user) 
and then return to the original caller's session, 
manually switching credentials and restoring them in `finally` blocks is cumbersome.

The `Api` interface provides the `runAs` convenience methods and the functional interface `ApiAction`:

[source,java]
----
	@FunctionalInterface
	public interface ApiAction {
	  void run() throws Exception;
	}
	
	void runAs(User user, ApiAction action) throws Exception;
	void runAs(User user, String password, ApiAction action) throws Exception;
----

`runAs` saves the current authentication (either `BasicAuth` or `BearerToken`), temporarily sets basic authentication to the specified user, runs the action, and guarantees restoring the original authentication in a `finally` block:

[source,java]
----
// Currently authenticated as admin
api.setBasicAuth("admin@scenario.com", "adminPassword");

// User created via createUserWithCredentials retains password in memory
User manager = api.getUsersApi()
	.createManagerWithCredentials("manager", "mgrPassword", "manager@example.com", 2);

// Execute an action authenticated as the manager:
api.runAs(manager, () -> {
    // Inside this block, API calls run with the manager's credentials
    logger.info("Executing as: {}", api.getAuthentication()); 
    api.getUsersApi()
    .createUserWithCredentials("player1", "playerPass", "player1@example.com");
});

// Original admin authentication is automatically restored
logger.info("Restored auth: {}", api.getAuthentication()); 
----

[NOTE]
====
Users returned from `createUserWithCredentials`, `createAdminWithCredentials`, and `createManagerWithCredentials` 
have their *plaintext password populated in memory* +
so `runAs(user, action)` can be used directly.

If the `User` object has no password set +
(e.g. when loaded from server Traccar omits the password field), + 
use the overload with the explicit password:

[source,java]
----
api.runAs(user, "userPassword", () -> {
    List<Device> userDevices = api.getDevicesApi().getDevices();
});
----
====


==== Server-Side Authentication

It is important to understand that we are programming a client that connects to Traccar.
If you login to the Traccar web interface, you are using a different authentication mechanism (session cookies) than the REST API. 
Therfore as an admin or manager you can list your users at `<host>/settings/users` 
and login as one of them in the web interface, _without knowing their password_.

This backdoor is available for admin or manager users, 
in case the created users login to the web interface and change their password.
Anyhow the password can not be explicitly read from the server.

In our client environment, we need to know the password of a user to authenticate as that user via the REST API.


=== Get Current Authentication

You can check which authentication is currently active:

[source,java]
----
// Check who is authenticated
String auth = api.getAuthentication();
logger.info("Currently authenticated as: {}", auth);

// Returns one of:
// - "ApiKey.BearerToken=<token>" for Bearer Token
// - "BasicAuth=<email>/ *****" for Basic Auth
// - null if no authentication is set

// Get Basic Auth details with password (not recommended for logging)
HttpBasicAuth basicAuth = api.getBasicAuth();
if (basicAuth != null) {
    String username = basicAuth.getUsername();
    String password = basicAuth.getPassword();
}
----

=== Error Handling

[source,java]
----
try {
    api.setBasicAuth("user@domain.com", "wrongPassword");
    User user = api.getUsersApi().getUser(123L);
} catch (ApiException e) {
    if (e.getMessage().contains("401")) {
        logger.error("Authentication failed - invalid credentials");
    } else if (e.getMessage().contains("403")) {
        logger.error("Access denied - insufficient permissions");
    } else {
        logger.error("API error: {}", e.getMessage());
    }
}
----
