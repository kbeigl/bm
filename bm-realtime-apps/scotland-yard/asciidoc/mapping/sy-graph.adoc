= The London Game Graph 

With the Scotland Yard game we want to explore *Digital Maps* and *Navigation Algorithms*. +
For navigation we need a digital map of London and a *Graph* representation of the game board. + 
The original Game Board provides the graph with stations as nodes and edges to move. +
Therefore we will first extract the graph representation of the game board + 
and then create a digital map of London with the help of OpenStreetMap.

Then we will implement a navigation algorithm to find the shortest path 
between two stations on the map and can be used be all players.
Especially automated players can use this algorithm for their own strategy implementation.

The London board is shipped as geo-referenced GeoJSON in

	src/main/resources/london.geojson
	
199 stations with WGS84
coordinates, all taxi / bus / underground / boat links of the original game. 

Actually the geojson file implicitly provides quite some *Game Rules*. +
We'll keep it simple and play without tickets, bariers, double moves, etc. +
We can store the start stations, the number of detectives, etc. +
This file will be used in the *Game Controller* to validate the moves of the players. +
And it can be used by the players to navigate the map and to develop their own strategies. 

The file `london.geojson` is a _read only_ file and should focus on the game rules and not on map processing. 
Nevertheless, it is a good idea to geocode the stations as a reference for map processing later. 
To keep the map precise, we have hand picked the stations and their geo coordinates with JOSM 
which is described in the next section.

.Scotland Yard Graph

The figures show the graph representation of `london.geojson` with all subway stations and connections. +
Thanks to georeferencing, the 14 subway stations are the correct geographic position. +
But you will also see that the connections are not following the real streets and subway lines. +
They are merely straight lines - called *Links* (`"kind": "link"`) - between the stations, +
which is sufficient for game control.



== Format

`london.geojson` is a standard https://datatracker.ietf.org/doc/html/rfc7946[RFC 7946] `FeatureCollection` and +
can be opened directly in JOSM, QGIS and many other GIS tools. + 
Coordinates are `[lon, lat]` in EPSG:4326.

=== Station features

One `Point` per station, `id` = `station-<no>`:

[source,json]
----
{
  "type": "Feature",
  "id": "station-13",
  "geometry": { "type": "Point", "coordinates": [-0.1239491, 51.530609] },
  "properties": {
    "kind": "station",
    "no": 13,
    "name": "King's Cross St Pancras",
    "start": true,
    "pixel": [534, 70],
    "geoSource": "osm",
    "osmNode": 119274464,
    "taxi": [4, 14, 23, 24],
    "bus": [14, 23, 52],
    "underground": [46, 67, 89],
    "boat": []
  }
}
----

And here is how it looks in JOSM:

.Station 13 in JOSM
image::../../diagrams/station13attribs.jpg[Station 13, width={scotland-yard-image-width}, link=../diagrams/station13attribs.jpg, window=_blank]

* `start` - one of the 18 start cards of the original game
* `pixel` - legacy position on the board image (for drawing on `london.jpg`)
* `geoSource` - `osm` for the 14 anchor stations with a known real position,
  `tps` for interpolated stations (see <<georeferencing>>)
* `taxi`, `bus`, `underground`, `boat` - neighbour station numbers per transport, +
   i.e. all possible *Moves* from this station. 

So the graph is fully encoded in the station features and any controller software +
can simply read the station number and get its neighbours.


=== Link features

One `LineString` per connection, `id` = `<transport>-<lower no>-<higher no>`. +
The legacy `VIA` stations are kept as intermediate vertices so the line follows
the printed route:

[source,json]
----
{
  "type": "Feature",
  "id": "underground-13-46",
  "geometry": { "type": "LineString", "coordinates": [[...], [...], ...] },
  "properties": { "kind": "link", "transport": "underground",
                  "from": 46, "to": 13, "via": [47, 34, 22, 23] }
}
----

Link-13-46 is a `LineString` with 5 vertices, the first and last are the stations, the others are the via stations. +

=== `board` member

The foreign member `board` carries everything that is not a geometry:

[source,json]
----
"board": {
  "name": "London",
  "formatVersion": "2.0",
  "stationCount": 199, "linkCount": 461,
  "startStations": [13, 26, 29, ...],
    ...
  },
  "georeference": { ... }
}
----


[[georeferencing]]
== Georeferencing

The printed board is a stylised map, not a projection, +
but it is close:
a plain affine fit gives ~8 m per pixel with a mean residual of ~110 m.

Fourteen stations are Underground stations drawn on the board +
whose real position is known and matched with OpenStreetMap:

[cols="1,3,1,1", options="header"]
|===
| no | name | affine residual | leave-one-out error
| 1   | St. John's Wood          | 157 m | 140 m
| 13  | King's Cross St Pancras  |  39 m |  66 m
| 46  | Baker Street             |  65 m |  65 m
| 67  | Holborn                  |  52 m |  43 m
| 74  | Paddington               | 102 m | 289 m
| 79  | Bond Street              | 100 m |  61 m
| 89  | Bank                     |  65 m |  54 m
| 93  | Queensway                | 271 m | 377 m
| 111 | Green Park               |  75 m | 168 m
| 128 | Elephant & Castle        | 107 m |  39 m
| 140 | Westminster              | 178 m | 234 m
| 153 | Victoria                 | 121 m |  60 m
| 163 | South Kensington         | 113 m | 422 m
| 185 | Vauxhall                 | 138 m | 274 m
|===

A thin-plate spline _pixel -> local metric plane_ is fitted through these
anchors (exact at the anchors, smooth in between) and applied to the other
185 stations. The leave-one-out test (drop one anchor, predict it from the
other 13) estimates the accuracy of the interpolated stations:
*median ~100 m, mean ~165 m, worst case ~420 m at the board edges*.



[[verification]]
=== Verification against legacy 

Running the generator with `--verify` compares the legacy
`stations_geo_estimate.csv` with the new board:

----
station   1: legacy (51.5347, -0.174)      -> new (51.5353523, -0.1742097)  distance    74 m
station  14: legacy (51.493421, -0.179528) -> new (51.531556, -0.114298)    distance  6193 m
all 199 stations: mean 2945 m, median 2634 m, max 7011 m
----

Station 1 (the only correctly identified legacy anchor) agrees within 74 m;
station 14 - and the rest of the board - was pulled kilometres to the
south-west by the wrong legacy anchors. 


=== Regenerating the board

[source,bash]
----
cd bm-realtime-apps/scotland-yard
python3 tools/board/build_london_geojson.py \
        --verify src/main/resources/boards/stations_geo_estimate.csv
----

Requires `numpy` and `scipy`. +
To improve the accuracy add more confirmed
stations to `ANCHORS` in the script and rerun.
